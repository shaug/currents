# Dependencies and reproducible qualification

Status: selected purposes and candidate pins, not a claim of production qualification. No dependency has been installed for this plan. CUR-001 owns resolution and security/license/MSRV review; CUR-006 owns actual encrypted linkage; CUR-004 owns Apple SDK qualification. Exact application resolution lives in the future committed Cargo.lock. Small focused libraries replace commodity implementations, not Currents' financial semantics. No ORM, event framework, web server, second SQLite stack or UI web shell.

## Selected additional commodity packages

Exact patches are deliberately **unqualified**, selected by the reproducible procedure below, not invented current versions. Initial major families constrain the search. If a family cannot pass the named proof, stop that gate and propose a reviewed replacement rather than silently reimplementing it.

OS crypto and SQLCipher do encryption. iOS QR parsing uses platform camera/QR APIs with explicit permission; no new cryptographic protocol. Add no blanket network permission to domain crates. Test-only Ledger and Beancount are independent subprocess oracles, not shipped runtime libraries; pin both versions/source and disclose their separate licenses.

## Exact-pin qualification procedure (CUR-001 and CUR-004)

1. Record current date, official registry/tag/source URL and license for every runtime/development/build dependency. Resolve the listed starting pins and proposed families in a fresh synthetic workspace. Select newest non-prerelease compatible patch within the chosen family **on that date**, then replace floating recommendations in tools/versions.lock.json with exact version, source commit or verified download SHA256, enabled features, Rust requirement and rationale. Commit the actual Cargo.lock in the implementation task. Registry checksum and signed vendor verification, when supplied, must match.
2. Run cargo metadata/tree for production target-feature combinations, Rust 1.99.0, and candidate MSRV1.94.0. Edition2024/resolver3. `rust-version=1.94` is a promise only after complete production build/test at1.94; otherwise record the exact incompatibility and deliberate reviewed MSRV increase. Never claim resolver fallback proves compatibility.
3. Select a currently vendor-supported stable full Xcode release with Swift 6 supporting deployment target macOS 15.0 and target iOS 18.0 (FinanceKit eligibility/API availability still separately gated), record exact Xcode build/SDK versions and Swift toolchain. Qualify minimum macOS 15 and current OS on actual machines; initial architecture arm64. CLT selection alone does not establish whether Xcode is installed. No system developer-directory changes without authorization.
4. Resolve exact versions/checksums for cargo-deny, cargo-nextest, cargo-llvm-cov, cargo-fuzz, cargo-cyclonedx, git-cliff, Gitleaks, cbindgen and actionlint. Pin every GitHub Action to full commit, with release/tag comment and update process. Use official sources, no copied stale workflow pins. Record chosen runner image identifiers and native compilers/crypto provider. Workflows cannot merge with placeholders or moving latest tags.
5. Execute the focused crate/tool smoke tests, JCS/calendar/numeric golden vectors, license/advisory scans, all-target locked builds and feature graph audit. Record result/version/command/output digest. Gate fails on unresolved vulnerability, license conflict or missing binary checksum unless an explicit owner-reviewed, scoped, expiring exception is permitted; no global suppression. Final app license choice remains a release-owner decision, not inferred from dependencies.
6. Verify cache-free build, then source-vendored `--frozen` offline build. Rebuild unsigned artifacts twice in equivalent controlled environments; report unexplained byte differences honestly. Requalify crypto/kernel updates with full replay, ciphertext, faults, ABI and restore suites. Weekly reviewed update PRs; urgent security changes separate. No unattended releases.
