## Why

Implement on-demand one-per-user currentsd Swift owner host embedding Rust, exclusive dataset writer, private XPC.

## Scope

Implement on-demand one-per-user currentsd Swift owner embedding Rust behind a private authenticated XPC bootstrap and exclusive dataset writer. Use a bundled owner executable, signed-helper integration points and SMAppService per-user LaunchAgent with native/LaunchAgents/com.currents.owner.plist MachServices bootstrap. Registration/denied/disabled/uninstalled states are explicit and setup requires permission; no private data before mutual UID/designated-identity checks on the live anonymous endpoint. Reconnect invalidates trust and preserves command identity. This ticket completes code and synthetic transport/registration-adapter tests without production credentials; actual signed installation, Keychain, LocalAuthentication and app-quit CLI/MCP proof is CUR-056. No TCP listener or direct client DB fallback.

- [ ] `cur_035_3`: single_writer:second owner process/duplicate writable dataset refused; orderly shutdown awaits Rust pools

- [ ] `cur_035_fresh_authorization_time`: Host binds identity/grant/instance but samples fresh trusted clock at every admission and queued execution;session older than capability expiry and queued command crossing expiry fail, regardless of saved ReadBasis or caller-supplied evaluation time.

Production credentials/entitlements are not prerequisites for these implementation suites; actual signed-owner and Apple proof belong to CUR-056/CUR-057. Missing required synthetic target is BLOCKED; synthetic success never passes production identity gates.
