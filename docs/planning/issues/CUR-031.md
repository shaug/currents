## Why

Implement staged restore/migrate/data-key rotation with typed input variants and owner-only CURRENT generation registry.

## Scope

Implement staged restore/migrate/data-key rotation with typed input variants and owner-only CURRENT generation registry. Exclusive lock/await close, new key persisted before activation, verified DB/sidecars+directories flushed before marker rename/directory flush. Reopen full audit before writes, retain old key/generation until required backup verified; retirement separate. Preserve original serialized authority with version readers/upcasters; older app refuses new incompatible format. Service GenerationCoordinator owns restore/migrate/rotate orchestration and consumes service VerifiedFullArchive; storage owns only generation filesystem/database primitives and never imports service/domain replay.
