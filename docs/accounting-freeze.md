# C05 frozen accounting, version 1

This synthetic private adapter freezes typed intents, not authorization or adoption.
`freeze(&AccountingIntent, &DomainState)` uses the committed C05 index at exactly
`DomainState.through`. The index is nonauthoritative and rebuilt from ordered
versioned frozen manifests and their verified content bytes. It pins the prior
native checkpoint v1 without changing that codec. Metadata declarations and
financial entries never share a batch; declarations must already be committed.

`AccountingBatchV1` carries schema/native version 1, ordered operations,
fixed-size prefix preconditions, prebinding decision digest and count expectations.
A bounded `FrozenAccountingManifestV1` authoritative record carries its ID,
versions, ContentReferenceV1 to RFC8785 ordered operation bytes, preconditions,
decision digest and result expectations. Actual native head/results are in the
outer commit, never in the prebinding input. The existing structured-record1MiB
limit and closure64MiB limit remain distinct. No text memo or salt enters native
operations. Generated Document bindings are derived after hashing and excluded
from their own hash; the ordered outer manifest also binds metadata operations.

A `DateConversionPolicyV1` has an exact ID/version, explicit civil conversion
(CivilOnly, fixed supplied UTC offset, or individually resolved instants with
zone/data-version/offset evidence), and disclosed bookkeeping fallback. A known
posting date selects booking; otherwise a known effective date requires explicit
fallback, and unknown originals require explicitly supplied bookkeeping. Source
TemporalValue bytes, precision, zone and original text remain untouched. Native
value date is the effective date or the documented mechanical booking placeholder.
Reversal uses the frozen original native dates and entry key, never current policy.
DatasetPolicy and HolidayCalendar are different roles and are not executable date
conversion policies. Storage checks only exact declared role references.

Native floor/end are 0001-01-01/9999-12-31. Account paths derive from complete
opaque account IDs, never names; supplied permanent unit codes are validated,
not generated by truncating tickers or UUIDs. Unit code/exponent and account
kind/path are immutable. USD exponent is2. Exact declared-unit divisibility,
scale18 conversion, i128::MIN and every ordered partial sum are checked. Explicit
half-even quantization and stable-ID largest-remainder allocation return their
remainder rather than hiding an adjustment in a journal.

Required vectors: cur_009_1 numeric boundaries/ties; cur_009_2 backfill, unknown
originals and both-date reversal; cur_009_3 collisions/exponent migration/date
range; cur_009_4 canonical frozen replay/hash binding, metadata native-head
mapping and no empty journal. Additional counterexamples cover corrupt frozen
bytes, stale index prefix, wrong date role/version, unmapped metadata, per-native
limits and outer manifest integrity. No production gates are enabled.
